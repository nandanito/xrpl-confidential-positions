### 1. HIGH — cross-row. E-304 asserts a corpus-wide negative over a corpus E-306 records as unobtained

E-304: *"no upstream text says which was intended."*

E-306's evidence cell names a document that is exactly the kind of upstream text that would say: *"a search of all 21 … finds only citations of `paper/cmpt-progress-and-changes.tex`, which is not in the repository."* A file named *progress and changes* to the very paper whose sentence is in dispute is the first place an erratum would be recorded, and this project has not obtained it.

E-304's `Not checked:` names *"whether a shared-C₁ layout was considered anywhere not public, and the May revision itself"*. It does not name `cmpt-progress-and-changes.tex`, which is neither of those — it is a public, cited, unobtained document.

Under the project's own rule, an unreachable primary source is a named gap and a correct output. The defect is not that it was unobtained; it is that a corpus-wide negative was asserted **over** it. Defensible version: *"no upstream text this project has read says which was intended, and `paper/cmpt-progress-and-changes.tex`, cited by upstream issues and absent from the repository, was not obtained."*

⚠ This matters beyond the row: **F-13 is one of the four filings.** Filing an erratum against a paper without having read the paper's own changes document is the first thing a maintainer will ask about.

### 2. HIGH — cross-row. E-306's *"the implementation is not affected"* holds only when `context_id` is non-NULL, and E-296 is the row that says so

E-306: *"F-17 still holds at mpt-crypto `1.0.5`, on reading, and so does its note that the implementation is not affected."* Its evidence: *"`proof_compact_standard.c` still hashes `context_id` into the statement hash its nonces are derived from, behind the same `if (context_id)`."*

The safety argument is that the implementation binds the transaction context even though the paper's statement omits it. Behind `if (context_id)` that argument is conditional, and **E-296 is the row establishing that the condition is not always met**: the same family of files *"silently accept a NULL context_id, omitting it from the hash when absent"*, and E-296 records the pattern in `proof_compact_standard.c` by name.

So on the NULL path the implementation is in exactly the position the paper describes, and the note *"the implementation is not affected"* is unqualified. Defensible version: *"…and so does its note that the implementation is not affected when a non-NULL `context_id` is supplied; on the NULL path that `if` omits it, which is E-296."*

⚠ **F-17 is one of the four filings**, and this is the qualification that decides what the filing is actually reporting.

### 3. HIGH — E-299's correction is contradicted by its own evidence cell

What the evidence does support is the narrower thing: `internal/mpt-crypto-sys` on `main` carries the same `1.0.4` pin, so *the pin* is no longer off-mainline even though *the published commit* is. Defensible version: *"…`'four tag-generations behind'` is true of `0.1.0-beta.1` only; `'not on the mainline branch'` still describes the published commit, which is diverged from `main`, but `main` now carries the same pin."*
