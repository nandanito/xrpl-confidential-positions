## 1. HIGH — the byte-level `Scalar` drop test reads through invalidated provenance

**FILE:** signer/src/scalar.rs:380

The test obtains `storage` through a shared reference:

> `let storage: *const u8 = held.as_bytes().as_ptr();`

It then creates an exclusive borrow and writes through it:

> `unsafe { std::mem::ManuallyDrop::drop(&mut held) };`

Finally it reads through the older shared-derived pointer:

> `std::ptr::read_volatile(storage.add(i))`

Owning the allocation keeps it live but does not preserve that pointer’s permission. The mutable reborrow used by `ManuallyDrop::drop`, followed by the destructor’s writes, invalidates the shared-derived pointer under both Stacked and Tree Borrows. The native pass proves only that this execution happened to produce zeros. This violates the aliasing principles summarized by the [Rust Reference](https://doc.rust-lang.org/stable/reference/behavior-considered-undefined.html#pointer-aliasing), and Miri checks both relevant models as described in the [Miri documentation](https://github.com/rust-lang/miri).

A sound construction is a `MaybeUninit<Scalar>` slot, obtaining `*mut Scalar` from `slot.as_mut_ptr()`, invoking `ptr::drop_in_place` through that same raw pointer, and then reading its `[u8; 32]` through the same provenance. `MaybeUninit` keeps the allocation alive and prevents a second automatic drop.

**Falsified by:** Miri accepting the original test under both default Stacked Borrows and `-Zmiri-tree-borrows`, without disabling alias checks.

**MEASURED / PREDICTED:** **MEASURED:** the prebuilt test passes natively, and the source has the sequence above. **PREDICTED:** Miri rejects the post-drop read; Miri could not be run because the read-only checkout prevents its build artifacts.
