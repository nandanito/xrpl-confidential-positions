## Question 5: The residuals

**Verdict: Question 5: no findings**

### 1. Accuracy of statements where recorded
- **Residual 1 (Unpinned ledger hash)**: Accurately stated in `REVIEW-059c` adjudication table (R1-9) and `web/hosted/README.md`. Code and docs confirm `LoopbackLedger.snapshot()` binds to the validated ledger sequence and verifies `network_id === DEVNET_NETWORK_ID`, while leaving the ledger hash unpinned.
- **Residual 2 (Network access during install/snapshot reaching loopback)**: Accurately stated in `ADR-0004`, `web/hosted/README.md`, `web/hosted/build.ts` header, and manifest. Specifically notes that on OrbStack, `host.docker.internal` allows container processes during `bun install` and `snapshot.ts` to contact services on the host's `127.0.0.1`, while container 2 runs with `--network none`.
- **Residual 3 (Dependency code modifying `/src` during build)**: Accurately stated in `web/hosted/README.md` and `web/hosted/build.ts`. Accurately documents that `checkExportedTree()` verifies the tree before container execution and cannot detect modifications made to `/src` during build execution.

### 2. Is any of them a fix that should have been made?
- **Ledger hash pinning**: **No.** Within D-H2's accepted risk model, the remote Devnet node pool is untrusted; an untrusted node could fabricate matching ledger hashes as easily as sequences. Furthermore, XRPL negative reads (`entryNotFound`) do not provide uniform ledger hashes across RPC calls, and enforcing hash requirements would introduce divergence between the shared TypeScript facility reader and the Rust signer (E-330).
- **Network isolation during install/snapshot**: **No.** Package installation requires network egress to download npm packages, and taking the snapshot inherently requires network access to the live Devnet WebSocket endpoint (`s.devnet.rippletest.net:51234`). Decoupling the build into two containers—running compilation and packaging in container 2 with `--network none`—provides the maximum practical containment without maintaining a complex local offline mirror.
- **Read-only source tree during build**: **No.** Vite and TanStack Start require writable working directories during compilation (`.vite`, `dist`, `.build`). Mounting `/src` read-only would require substantial toolchain rearchitecting. Downstream integrity is instead rigorously protected by the hosted gate (`runChecks()`), preflight, and browser checks over the compiled output.
