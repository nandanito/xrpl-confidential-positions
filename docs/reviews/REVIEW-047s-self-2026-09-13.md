## Findings

### S1. MEDIUM — the disclosure names one of two ways the issuer can freeze the float

`facility/src/custody.ts` says the bank *"can freeze it by enabling a lock and setting it"*. The request's *Who else holds power* section and `REVIEW-046c` H1 name the same single mechanism.

There is a second, and it takes one transaction. `RequireAuth` is mutable by default: it is in `MPTokenIssuanceSet.h`'s `flagMapping`, and `doApply` sets an enabled flag with no condition on existing holders (`MPTokenIssuanceSet.cpp:299-312`). Once the issuance requires authorisation, `requireAuth` returns `tecNO_AUTH` for any holder whose `MPToken` lacks `lsfMPTAuthorized` (`MPTokenHelpers.cpp:420-422`). `ConfidentialMPTSend` checks both parties (`:253`, `:256`), and `ConvertBack` (`:202`) and `MergeInbox` (`:73`) check the account.

**Live state, read from Devnet on 2026-09-13 at validated ledger 5285912:** the facility issuance's `Flags` are `224` (`CanTransfer | CanClawback | CanHoldConfidentialBalance`) with no `ImmutableFlags`, and the Dedicated Account's `MPToken` has `Flags: 0`, so `lsfMPTAuthorized` is not set (`LedgerFormats.h:195`). **Not executed.**

It is the same credential and the same power, immobilising the float, so it is not the class round two's stopping condition names. The disclosure's wording presents one mechanism as the way, and the request's bullet does too.

### S2. MEDIUM — the architecture document still says nobody has asked who holds the key

`docs/architecture/ARCHITECTURE-2026-08-18.md:275`, in §5's list of what is open: *"The facility's whole float therefore sits under one ordinary key, and no review has asked who holds it."* `REVIEW-046` asked, B-27 is ruled, and *"one ordinary key"* is the framing H1 found incomplete. E-117's copy and ADR-0002's copy of the same clause were struck in `74bf9a1`; this one was not. **The architecture document is the authority on which gates remain shut**, so the stale copy is in the worst place for one. Found by grepping for the phrase.

### S3. LOW — ADR-0002's custody row states the Vault clawback without its condition

The row says *"the asset's issuer can claw back from the vault (`VaultClawback.cpp:167-187`)"*. That path requires the asset's issuance to carry `lsfMPTCanClawback` (`VaultClawback.cpp:187`). The facility's own issuance does, which is why H1 applies, but the sentence reads as unconditional.
